# handwired × Sprite：從神經訊號到像素的可微分動畫管線

> 目標：把**神經傳導 → 肌肉 → 關節動力學 → 骨架運動學 → 蒙皮 → 像素化**整條鏈，全部寫成「乘、加、ReLU」的手寫網路。
> 規則由公式直接決定，不需要訓練資料；但整條鏈可微分，所以之後可以拿現成的 sprite sheet 解凍部分權重來微調。

> ⚠️ **查證狀態**：本文撰寫時**未進行即時檢索**，內容根據既有知識整理。
> 證據等級：✅ 經典、廣為引用的公式或資源｜⚠️ 數值或細節需再核對原文｜❌ 尚未驗證的構想。

## 0. 一張圖看懂

```
 L0 神經驅動         L1 肌肉          L2 關節動力學      L3 骨架 FK        L4 蒙皮          L5 像素化
 CPG / LIF   ──a(t)──▶ Hill 簡化 ──τ──▶ 彈簧阻尼+限位 ──θ──▶ 矩陣連乘 ──Tᵢ──▶ LBS 權重 ──p'──▶ 反向取樣+取整
 (ReLU=發放)       (分段線性)      (半隱式 Euler)     (越末端動越多)    (距離衰減)       (訓練用雙線性)
                                                                     ▲
                                              L6 次級運動（頭髮、披風：Verlet 彈簧）
```

每一層都只輸出一組數字給下一層。這樣**每層都是一個獨立原語**，可以替換：例如 L0 改成鍵盤輸入，或略過 L0–L2，直接手 K 角度 θ。

### 1.2 可微分圖像與網路

| 方法 | 跟這條管線的關係 | 等級 |
|---|---|---|
| Spatial Transformer Networks（Jaderberg et al., 2015） | 「仿射矩陣 + 雙線性取樣」本身就可微分，等同 L3＋L5 的訓練版 | ✅ |
| 可微分光柵化（如 SoftRas、DiffVG） | 讓「形狀 → 像素」的梯度能回傳 | ✅ |
| Pix2Pix／GAN 類 sprite 生成 | 黑盒，產出品質高但無法解釋。可以當 L5 之後的「上色／修飾」頭 | ⚠️ |
| Neural ODE | 把 L2 的動力學視為連續時間模型來訓練 | ✅ |

### 1.3 物理與人體力學公式

| 公式 | 層 | 等級 |
|---|---|---|
| 旋轉：p' = R(θ)(p − c) + c，位移 ≈ r·θ | L3 | ✅ |
| 前向運動學：T_child = T_parent · R(θᵢ) · Trans(Lᵢ) | L3 | ✅ |
| Linear Blend Skinning：p' = Σ wᵢ Tᵢ p（Magnenat-Thalmann et al., 1988） | L4 | ✅ |
| Dual Quaternion Skinning（Kavan et al., 2007）：改善 LBS 在關節處的「糖果紙」塌陷 | L4 | ✅ |
| 彈簧阻尼：τ = −k(θ − θ₀) − cω；臨界阻尼 c = 2√(kI) | L2 | ✅ |
| 半隱式 Euler：ω += (τ/I)dt；θ += ω·dt | L2 | ✅ |
| Verlet 積分：x_{t+1} = 2x_t − x_{t−1} + a·dt² | L6 | ✅ |
| Position Based Dynamics（Müller et al., 2007）：用距離約束處理布料、頭髮 | L6 | ✅ |
| IK：CCD、FABRIK（Aristidou & Lasenby, 2011）：從手腳目標反推角度 | L3（反向） | ✅ |
| 人體節段比例（Winter，引自 Drillis & Contini）：以身高 H 為單位，上臂約 0.186H、前臂約 0.146H、手約 0.108H、大腿約 0.245H、小腿約 0.246H | L3 參數 | ⚠️ 數值要對原書 |
| 關節活動範圍：例如膝關節約 0°～140° 屈曲，肘約 0°～145° | L2 限位 | ⚠️ 依文獻與族群而異 |

### 1.4 肌肉與神經公式

| 公式 | 層 | 等級 |
|---|---|---|
| Hill 肌肉模型（Hill, 1938）：F = a · F_max · f_L(l) · f_V(v) + F_passive | L1 | ✅ 形式；⚠️ 曲線參數 |
| 肌肉激活動力學：da/dt = (u − a)/τ_act，τ 約數十毫秒 | L1 | ✅ 形式；⚠️ 時間常數 |
| Hodgkin–Huxley（1952）：完整離子通道模型 | L0 | ✅；但對動畫來說太重 |
| Leaky Integrate-and-Fire（LIF）：τ dV/dt = −(V − V_rest) + RI，超過閾值就發放 | L0 | ✅ |
| 中樞模式產生器（CPG）：Matsuoka 振盪器（1985），兩個互相抑制的神經元產生節律 | L0 | ✅ |
| 神經傳導延遲：Δt = 距離 / 傳導速度（有髓鞘大纖維可達數十 m/s） | L0→L1 | ✅ 形式；⚠️ 數值 |

> 😲 **驚奇面向**：Matsuoka 振盪器的輸出原本就寫成 `y = max(0, x)`，**它本來就是 ReLU 網路**。這可能是生物模型跟 handwired 最自然的接點：步態節律不需要額外轉換，直接就是手寫權重。

## 2. 每一層怎麼變成「乘、加、ReLU」

| 層 | 原本的公式 | handwired 寫法 |
|---|---|---|
| L0 LIF 發放 | `if (V > θ) spike` | 用 ReLU 階梯：`spike = relu(V−θ)/ε − relu(V−θ−ε)/ε`。訓練時把 ε 放大，讓梯度不會是 0 |
| L0 CPG | Matsuoka | 原本就是 `max(0, ·)`，直接照抄 |
| L1 力長曲線 f_L | 鐘形曲線 | 分段線性：三個 ReLU 拼成梯形 |
| L1 激活 | `da/dt = (u − a)/τ` | 線性的：`a += (u − a)·dt/τ` |
| L2 關節限位 | `clamp(θ, lo, hi)` | 硬限位：`lo + relu(θ−lo) − relu(θ−hi)`；軟限位：額外加回彈力矩 `−k·relu(θ−hi) + k·relu(lo−θ)` |
| L2 積分 | Euler | 線性，本來就是乘和加 |
| L3 旋轉 | cos θ、sin θ | 有三種做法：① θ 當外部參數，R 在層外算好（最簡單）；② 用分段線性逼近 sin 和 cos；③ 狀態直接存 (cos, sin)，旋轉增量 = 小角度矩陣相乘，**全程線性** |
| L3 FK | 矩陣連乘 | 矩陣乘法 |
| L4 LBS | Σ wᵢ Tᵢ p | 權重矩陣 W（像素數 × 骨頭數），是一張可以手寫的表 |
| L4 距離權重 | wᵢ ∝ 1/d | `relu(1 − d/R)` 錐形衰減，再做正規化 |
| L5 取整 | `round(x)` | ReLU 階梯（handwired 本來就有）；訓練時改用雙線性取樣 |
| L6 Verlet | 位置更新 | 線性；距離約束的長度要開根號，可以用分段線性逼近 |

### 你的「越遠動越多」在哪一層實現？

- **單一部件**：L3 的 r·θ。
- **部件連動**：L3 的矩陣連乘。指尖的位移 = 肩、肘、腕三段旋轉的疊加，所以末端動最多。
- **柔性過渡**：L4 的權重表。關節附近的像素同時受兩根骨頭影響，不會斷開。
- **延遲甩動**（鞭子、頭髮）：L6，或在 L0→L1 加上傳導延遲。末端比根部晚動、擺幅更大。這是「越遠影響越大」在**時間**上的版本。

## 3. 訓練策略：先凍結，再局部解凍

1. **全凍結**：所有權重都由公式和人體比例決定。這時已經可以動，而且每個數字都能解釋。
2. **解凍 L0、L1 的少數參數**：CPG 頻率、肌肉增益。目標是 LPC 行走影格；損失 = 渲染結果與目標影格的像素差（L5 用雙線性取樣）。
3. **解凍 L4 權重表**：讓關節處的變形更貼近畫師的手繪。
4. **永遠保持凍結**：骨架拓樸、關節限位。這些是「物理上不可違反」的規則，也是比黑盒生成模型好的地方。

> ⚖️ **反方觀點與限制**
> - 像素畫的魅力常來自畫師**刻意違反物理**（誇張、變形、抽格）。純物理管線產出的動作可能「正確但無聊」。對策是在 L3 之後加一層「風格偏移」，讓它可以訓練。
> - ReLU 階梯在訓練時梯度是 0。要靠「訓練用連續值、顯示時才取整」（直通估計，straight-through）來處理，這是近似。
> - 2D sprite 沒有深度。手臂繞到身體後面時的圖層順序，需要另外用規則判斷（可以用 ReLU 寫成 if-else）。
> - 完整的 Hill 模型和 HH 模型對遊戲動畫來說太重，實務上 L0 和 L1 多半會簡化成「CPG + 線性增益」。

## 4. 可執行範例

## 6. 實作進度：全身 3D 骨架與反推（`examples/body-rig.html`）

- 15 根骨頭、22 個自由度（屈伸＋外展）的 3D 骨架，同時正交投影成正面、側面兩張 81×144 像素圖。
- **雙視角反推**（6 個隨機目標，逐關節試探）：關節位置平均誤差，只看正面 6.2 px、只看側面 7.3 px、雙視角 1.3 px。
- **軟渲染 + 解析梯度**：像素佔有率 σ(有號距離/τ)、依深度加權的軟遮擋；梯度一路解析回傳：像素 → 形狀邊界與深度 → 投影端點 → 運動鏈雅可比（旋轉軸 × 力臂）。用 Adam 更新，τ 由 6 px 收窄到 0.5 px，最後以小步長試探收尾。
  - 梯度檢查：τ = 2 px 時，與數值梯度的 cos 相似度為 0.89。τ 越小，越受截斷與離散化影響，兩者越不一致。
  - 8 個隨機目標（雙視角）的比較：

    | 方法 | 位置誤差平均 | 位置誤差中位數 | 平均時間 | 平均評估次數 |
    |---|---|---|---|---|
    | 逐關節試探 | 1.1 px | 1.2 px | 10.9 s | 6006 |
    | 梯度下降 | 3.2 px | 1.3 px | 6.6 s | 1529 |

  - 解讀：梯度下降快約 1.6 倍，收斂時常更準（最佳 0.3 px），但 8 次中有 2 次卡在局部最小值（位置誤差最大 36～50 px）。逐關節試探較慢，但比較穩定。
- **混合式**（預設）：梯度下降（2 個起點）之後，統計哪個部位（軀幹、四肢）不吻合的像素最多，只對那個部位與它的對側肢體重來。候選角度包括各預設姿勢、16 組隨機角度，以及「與對側肢體互換」，挑出最好的兩組局部重跑梯度下降，變好才保留，最多 3 輪。
  - 12 個隨機目標（雙視角）：關節位置誤差平均 0.6 px、中位數 0.5 px，每題的最大誤差平均 1.6 px；**0 次失敗**（最大誤差 > 10 px 算失敗），角度平均誤差 4.2°，平均 15.6 s。
  - 相較之下，逐關節試探是平均 1.1 px、11 s；梯度下降是平均 5.0 px、6 s，8 題中有 6 題失敗（這組數字是加入「左右互換」之前測的）。
  - 「左右互換」候選專門處理側面圖中兩腿或兩手交錯造成的錯配。加入它之前，混合式 8 題仍有 1 題失敗。

### 6.1 第 3 項：接上 LPC 影格

- **素材**：LPC 男性基本角色（身體＋頭）的走路影格，正面朝下、側面朝右，各 9 格；現在收在 `examples/assets/lpc-atlas.png` 的第 1 組（見 6.4）。作者與授權見 `examples/assets/LPC-CREDITS.md`。本環境連不到 OpenGameArt，所以改從 Universal LPC Spritesheet Character Generator 的 GitHub 鏡像取得。
- **LPC 體型**：依站姿影格量出比例（身高約 47 px、頭約佔 1/3、腿只有 11 px），放大 2 倍；腿用前後兩顆膠囊做出「正面窄、側面厚」的截面。
  - 校正前，站姿的輪廓重疊率（IoU）是正面 82%、側面 68%；校正後不必反推就有 89%、88%。
- **損失**：LPC 只有輪廓，所以改用前景 / 背景的輪廓損失，並加上兩項：
  - 自然姿勢先驗：Σ((θ − μ)/σ)²。
  - 走路循環中與上一格的平滑項：σ = 20°。
- **結果**（混合式，9 格）：輪廓重疊率平均正面 89.8%、側面 85.6%，全程約 138 s。
  - 只用輪廓、不加先驗時，重疊率差不多（90.1%／87.4%），但會出現膝蓋彎到 145°、手臂擺到身後藏起來這類不自然的姿勢。加上先驗和平滑項後，膝蓋最多約 17°，左右髖也會交替擺動。
- **已知限制**：
  - 正面重疊率比修正頭部前少約 1 個百分點（見 6.2）。
  - 正面和側面同一格編號是否真的是同一時刻，只是假設。
  - 只有輪廓時，被身體遮住的四肢原本就無法唯一判定。

### 6.2 修正 LPC 頭部的點頭偏差

- **病因**：舊模型的頭和軀幹在側面都比 LPC 偏前約 2～3 px，LPC 的背也比較厚。反推為了蓋住背後，就讓軀幹後仰約 6°，頭再用點頭往前補回來。所以這是頭和軀幹前後位置的偏差，不只是頭形不對。
- **修法**：把骨架擺成直立（骨盆、脊椎、頸部的角度歸零），四肢沿用反推結果，再用座標下降法調整頭、下巴、軀幹的位置，讓 9 格雙視角第 30～106 列的不吻合像素最少（6546 → 4640）。結果是頭往下移 2 px、往後移 3 px，軀幹往後移 3 px，頭形大小不變。
- **結果**（混合式，9 格，同一台機器前後對照）：

| | 平均點頭角度絕對值 | 脊椎前彎 | 正面 IoU | 側面 IoU |
|---|---|---|---|---|
| 修正前 | 22.4°（每格 +15～+32°） | −4～−9° | 89.8% | 85.6% |
| 修正後 | 5.0°（−9～+9°） | −6～+4° | 88.7% | 85.8% |

- 只改前後位置、頭不往下移時，平均點頭 9.7°，重疊率 88.9%／86.4%。最後選了點頭角度較小的版本。
- 歪頭角度（正面）在第 4、8 格仍有約 ±14°，還沒處理。

### 6.3 步態移植到寫實體型

- 兩種體型共用同一組 22 個自由度，所以「套用到寫實體型」按鈕把反推出的 9 格角度原封不動套上，以每格 110 ms 循環播放。
- 沒有做比例換算：LPC 腿短頭大，同樣的角度在寫實體型上步幅會比較大。
- 反推出的髖外展有時達 −19°（內收），寫實體型的正面會看到雙腿往中線交叉。這是 LPC 腿在正面幾乎重疊造成的，還沒處理。

### 6.4 多角色與揮砍、施法

- **素材**：`examples/assets/lpc-atlas.png` 收了 5 組角色（男、女、壯碩男、少女、女・小頭），每組 3 個動作（走路 9 格、揮砍 6 格、施法 7 格），各有正面與側面。來源與授權見 `LPC-CREDITS.md`。
- **體型校正**：其他角色的體型都從男性參數出發，自動調整頭、下巴、軀幹的位置與半徑、肩寬、髖寬、四肢粗細。做法和 6.2 相同：用坐標下降法，讓幾格影格的輪廓不吻合像素最少，輪廓不吻合減少約 25～47%。壯碩男只用走路校正時，手臂抬起來後點頭偏差約 20°；把揮砍、施法的影格也一起拿來校正後才改善。
- **揮砍、施法的反推設定**：
  - 肩、肘的先驗放寬：肩前舉的 σ 從 35° 放寬到 90°，外展從 25° 到 70°，肘從 30° 到 60°。
  - 前後格的平滑項 σ 從 20° 放寬到 45°。原本是 20°，動作變化快的揮砍因此被拉回上一格，手臂抬不起來：少女的肩最大只有 6°。
  - 另外強制從「單手往前抬 90°」的姿勢起跑。
- **結果**（混合式；IoU 依序為正面／側面；「頭部絕對俯仰」= 骨盆前傾＋脊椎前彎＋點頭）：

### 6.5 動漫體型（6 頭身）與衣物物理（L6）

- **為什麼要做**：LPC 體型是為了對齊 Q 版輪廓而擬合的，頭約佔身高 1/3，腿是手的 2～3 倍粗。深蹲這類 LPC 沒有的動作，看起來會擠成一團。動漫體型只負責呈現，不拿來反推。
- **比例**：頭高約身高的 1/6，髖關節以下約佔一半；四肢各用一顆膠囊（大腿半徑 4.4、上臂 2.8）；腰細、肩窄，胸廓比例中性。臉用大眼睛色塊（瞳孔、高光）和較低的瀏海表現。
- **衣物物理**：用 Verlet 質點，每步更新 x ← x + (x − x_prev)(1 − 阻尼) + g·dt²，再反覆套用以下兩種修正：
  - 距離約束：兩個質點之間保持原本的距離。
  - 碰撞：p += n·ReLU(r − |p − c|)，碰到碰撞體就沿法線推出去。
  - 兩者都只用到乘、加、ReLU。
  - 雙馬尾：每邊 6 個質點（根部固定在頭上），會碰撞頭、胸、肩。
  - 短裙：12 條從腰部垂下的鏈，每條 4 個質點（根部固定在骨盆上）；同一層相鄰的鏈互相牽住，維持裙擺的圓周。碰撞體是骨盆（球）和兩條大腿（膠囊）。
  - 物理關閉時，或剛換姿勢時，用大阻尼直接算 80 步，讓衣物停在靜止狀態。
- **實測**：
  - 停止走路 4 秒後，質點最大速度 0.0006 px／幀，表示會靜下來。
  - 裙子穿入大腿碰撞體的最大深度：深蹲 0.54 px、踢腿 0、走路 0。碰撞體半徑 6.4，比大腿本身多 2 px 的餘裕，所以看不到穿模。
- **已知限制**：
  - 裙子由細膠囊拼成，邊緣有鋸齒。
  - 頭髮沒有和手臂碰撞，手舉過頭時可能穿過頭髮。
  - 物理步長跟隨畫面更新率，畫面卡頓時晃動幅度會變小。
