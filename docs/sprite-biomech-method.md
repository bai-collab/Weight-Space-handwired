# handwired × Sprite：從神經訊號到像素的可微分動畫管線

> 目標：把**神經傳導 → 肌肉 → 關節動力學 → 骨架運動學 → 蒙皮 → 像素化**整條鏈，全部寫成「乘、加、ReLU」的手寫網路。
> 規則由公式直接決定，不需要訓練資料；但整條鏈可微分，所以之後可以拿現成的 sprite sheet 解凍部分權重來微調。

> ⚠️ **查證狀態**：本文撰寫時**未進行即時檢索**，內容根據既有知識整理。
> 證據等級：✅ 經典、廣為引用的公式或資源｜⚠️ 數值或細節需再核對原文｜❌ 尚未驗證的構想。

## 0. 一張圖看懂

```
 L0 神經驅動         L1 肌肉          L2 關節動力學      L3 骨架 FK        L4 蒙皮          L5 像素化
 CPG / LIF   ──a(t)──▶ Hill 簡化 ──τ──▶ 彈簧阻尼+限位 ──θ──▶ 矩陣連乘 ──Tᵢ──▶ LBS 權重 ──p'──▶ 反向取樣+取整
 (ReLU=發放)       (分段線性)      (半隱式 Euler)     (越末端動越多)    (距離衰減)       (訓練用雙線性)
                                                                     ▲
                                              L6 次級運動（頭髮、披風：Verlet 彈簧）
```

每一層都只輸出一組數字給下一層。這樣**每層都是一個獨立原語**，可以替換：例如 L0 改成鍵盤輸入，或略過 L0–L2，直接手 K 角度 θ。

### 1.2 可微分圖像與網路

| 方法 | 跟這條管線的關係 | 等級 |
|---|---|---|
| Spatial Transformer Networks（Jaderberg et al., 2015） | 「仿射矩陣 + 雙線性取樣」本身就可微分，等同 L3＋L5 的訓練版 | ✅ |
| 可微分光柵化（如 SoftRas、DiffVG） | 讓「形狀 → 像素」的梯度能回傳 | ✅ |
| Pix2Pix／GAN 類 sprite 生成 | 黑盒，產出品質高但無法解釋。可以當 L5 之後的「上色／修飾」頭 | ⚠️ |
| Neural ODE | 把 L2 的動力學視為連續時間模型來訓練 | ✅ |

### 1.3 物理與人體力學公式

| 公式 | 層 | 等級 |
|---|---|---|
| 旋轉：p' = R(θ)(p − c) + c，位移 ≈ r·θ | L3 | ✅ |
| 前向運動學：T_child = T_parent · R(θᵢ) · Trans(Lᵢ) | L3 | ✅ |
| Linear Blend Skinning：p' = Σ wᵢ Tᵢ p（Magnenat-Thalmann et al., 1988） | L4 | ✅ |
| Dual Quaternion Skinning（Kavan et al., 2007）：改善 LBS 在關節處的「糖果紙」塌陷 | L4 | ✅ |
| 彈簧阻尼：τ = −k(θ − θ₀) − cω；臨界阻尼 c = 2√(kI) | L2 | ✅ |
| 半隱式 Euler：ω += (τ/I)dt；θ += ω·dt | L2 | ✅ |
| Verlet 積分：x_{t+1} = 2x_t − x_{t−1} + a·dt² | L6 | ✅ |
| Position Based Dynamics（Müller et al., 2007）：用距離約束處理布料、頭髮 | L6 | ✅ |
| IK：CCD、FABRIK（Aristidou & Lasenby, 2011）：從手腳目標反推角度 | L3（反向） | ✅ |
| 人體節段比例（Winter，引自 Drillis & Contini）：以身高 H 為單位，上臂約 0.186H、前臂約 0.146H、手約 0.108H、大腿約 0.245H、小腿約 0.246H | L3 參數 | ⚠️ 數值要對原書 |
| 關節活動範圍：例如膝關節約 0°～140° 屈曲，肘約 0°～145° | L2 限位 | ⚠️ 依文獻與族群而異 |

### 1.4 肌肉與神經公式

| 公式 | 層 | 等級 |
|---|---|---|
| Hill 肌肉模型（Hill, 1938）：F = a · F_max · f_L(l) · f_V(v) + F_passive | L1 | ✅ 形式；⚠️ 曲線參數 |
| 肌肉激活動力學：da/dt = (u − a)/τ_act，τ 約數十毫秒 | L1 | ✅ 形式；⚠️ 時間常數 |
| Hodgkin–Huxley（1952）：完整離子通道模型 | L0 | ✅；但對動畫來說太重 |
| Leaky Integrate-and-Fire（LIF）：τ dV/dt = −(V − V_rest) + RI，超過閾值就發放 | L0 | ✅ |
| 中樞模式產生器（CPG）：Matsuoka 振盪器（1985），兩個互相抑制的神經元產生節律 | L0 | ✅ |
| 神經傳導延遲：Δt = 距離 / 傳導速度（有髓鞘大纖維可達數十 m/s） | L0→L1 | ✅ 形式；⚠️ 數值 |

> 😲 **驚奇面向**：Matsuoka 振盪器的輸出原本就寫成 `y = max(0, x)`，**它本來就是 ReLU 網路**。這可能是生物模型跟 handwired 最自然的接點：步態節律不需要額外轉換，直接就是手寫權重。

## 2. 每一層怎麼變成「乘、加、ReLU」

| 層 | 原本的公式 | handwired 寫法 |
|---|---|---|
| L0 LIF 發放 | `if (V > θ) spike` | 用 ReLU 階梯：`spike = relu(V−θ)/ε − relu(V−θ−ε)/ε`。訓練時把 ε 放大，讓梯度不會是 0 |
| L0 CPG | Matsuoka | 原本就是 `max(0, ·)`，直接照抄 |
| L1 力長曲線 f_L | 鐘形曲線 | 分段線性：三個 ReLU 拼成梯形 |
| L1 激活 | `da/dt = (u − a)/τ` | 線性的：`a += (u − a)·dt/τ` |
| L2 關節限位 | `clamp(θ, lo, hi)` | 硬限位：`lo + relu(θ−lo) − relu(θ−hi)`；軟限位：額外加回彈力矩 `−k·relu(θ−hi) + k·relu(lo−θ)` |
| L2 積分 | Euler | 線性，本來就是乘和加 |
| L3 旋轉 | cos θ、sin θ | 有三種做法：① θ 當外部參數，R 在層外算好（最簡單）；② 用分段線性逼近 sin 和 cos；③ 狀態直接存 (cos, sin)，旋轉增量 = 小角度矩陣相乘，**全程線性** |
| L3 FK | 矩陣連乘 | 矩陣乘法 |
| L4 LBS | Σ wᵢ Tᵢ p | 權重矩陣 W（像素數 × 骨頭數），是一張可以手寫的表 |
| L4 距離權重 | wᵢ ∝ 1/d | `relu(1 − d/R)` 錐形衰減，再做正規化 |
| L5 取整 | `round(x)` | ReLU 階梯（handwired 本來就有）；訓練時改用雙線性取樣 |
| L6 Verlet | 位置更新 | 線性；距離約束的長度要開根號，可以用分段線性逼近 |

### 你的「越遠動越多」在哪一層實現？

- **單一部件**：L3 的 r·θ。
- **部件連動**：L3 的矩陣連乘。指尖的位移 = 肩、肘、腕三段旋轉的疊加，所以末端動最多。
- **柔性過渡**：L4 的權重表。關節附近的像素同時受兩根骨頭影響，不會斷開。
- **延遲甩動**（鞭子、頭髮）：L6，或在 L0→L1 加上傳導延遲。末端比根部晚動、擺幅更大。這是「越遠影響越大」在**時間**上的版本。

## 3. 訓練策略：先凍結，再局部解凍

1. **全凍結**：所有權重都由公式和人體比例決定。這時已經可以動，而且每個數字都能解釋。
2. **解凍 L0、L1 的少數參數**：CPG 頻率、肌肉增益。目標是 LPC 行走影格；損失 = 渲染結果與目標影格的像素差（L5 用雙線性取樣）。
3. **解凍 L4 權重表**：讓關節處的變形更貼近畫師的手繪。
4. **永遠保持凍結**：骨架拓樸、關節限位。這些是「物理上不可違反」的規則，也是比黑盒生成模型好的地方。

> ⚖️ **反方觀點與限制**
> - 像素畫的魅力常來自畫師**刻意違反物理**（誇張、變形、抽格）。純物理管線產出的動作可能「正確但無聊」。對策是在 L3 之後加一層「風格偏移」，讓它可以訓練。
> - ReLU 階梯在訓練時梯度是 0。要靠「訓練用連續值、顯示時才取整」（直通估計，straight-through）來處理，這是近似。
> - 2D sprite 沒有深度。手臂繞到身體後面時的圖層順序，需要另外用規則判斷（可以用 ReLU 寫成 if-else）。
> - 完整的 Hill 模型和 HH 模型對遊戲動畫來說太重，實務上 L0 和 L1 多半會簡化成「CPG + 線性增益」。

## 4. 可執行範例

## 6. 實作進度：全身 3D 骨架與反推（`examples/body-rig.html`）

- 15 根骨頭、22 個自由度（屈伸＋外展）的 3D 骨架，同時正交投影成正面、側面兩張 81×144 像素圖。
- **雙視角反推**（6 個隨機目標，逐關節試探）：關節位置平均誤差，只看正面 6.2 px、只看側面 7.3 px、雙視角 1.3 px。
- **軟渲染 + 解析梯度**：像素佔有率 σ(有號距離/τ)、依深度加權的軟遮擋；梯度一路解析回傳：像素 → 形狀邊界與深度 → 投影端點 → 運動鏈雅可比（旋轉軸 × 力臂）。用 Adam 更新，τ 由 6 px 收窄到 0.5 px，最後以小步長試探收尾。
  - 梯度檢查：τ = 2 px 時，與數值梯度的 cos 相似度為 0.89。τ 越小，越受截斷與離散化影響，兩者越不一致。
  - 8 個隨機目標（雙視角）的比較：

    | 方法 | 位置誤差平均 | 位置誤差中位數 | 平均時間 | 平均評估次數 |
    |---|---|---|---|---|
    | 逐關節試探 | 1.1 px | 1.2 px | 10.9 s | 6006 |
    | 梯度下降 | 3.2 px | 1.3 px | 6.6 s | 1529 |

  - 解讀：梯度下降快約 1.6 倍，收斂時常更準（最佳 0.3 px），但 8 次中有 2 次卡在局部最小值（位置誤差最大 36～50 px）。逐關節試探較慢，但比較穩定。
- **混合式**（預設）：梯度下降（2 個起點）之後，統計哪個部位（軀幹、四肢）不吻合的像素最多，只對那個部位與它的對側肢體重來。候選角度包括各預設姿勢、16 組隨機角度，以及「與對側肢體互換」，挑出最好的兩組局部重跑梯度下降，變好才保留，最多 3 輪。
  - 12 個隨機目標（雙視角）：關節位置誤差平均 0.6 px、中位數 0.5 px，每題的最大誤差平均 1.6 px；**0 次失敗**（最大誤差 > 10 px 算失敗），角度平均誤差 4.2°，平均 15.6 s。
  - 相較之下，逐關節試探是平均 1.1 px、11 s；梯度下降是平均 5.0 px、6 s，8 題中有 6 題失敗（這組數字是加入「左右互換」之前測的）。
  - 「左右互換」候選專門處理側面圖中兩腿或兩手交錯造成的錯配。加入它之前，混合式 8 題仍有 1 題失敗。

### 6.1 第 3 項：接上 LPC 影格

- **素材**：LPC 男性基本角色（身體＋頭）的走路影格，正面朝下、側面朝右，各 9 格；現在收在 `examples/assets/lpc-atlas.png` 的第 1 組（見 6.4）。作者與授權見 `examples/assets/LPC-CREDITS.md`。本環境連不到 OpenGameArt，所以改從 Universal LPC Spritesheet Character Generator 的 GitHub 鏡像取得。
- **LPC 體型**：依站姿影格量出比例（身高約 47 px、頭約佔 1/3、腿只有 11 px），放大 2 倍；腿用前後兩顆膠囊做出「正面窄、側面厚」的截面。
  - 校正前，站姿的輪廓重疊率（IoU）是正面 82%、側面 68%；校正後不必反推就有 89%、88%。
- **損失**：LPC 只有輪廓，所以改用前景 / 背景的輪廓損失，並加上兩項：
  - 自然姿勢先驗：Σ((θ − μ)/σ)²。
  - 走路循環中與上一格的平滑項：σ = 20°。
- **結果**（混合式，9 格）：輪廓重疊率平均正面 89.8%、側面 85.6%，全程約 138 s。
  - 只用輪廓、不加先驗時，重疊率差不多（90.1%／87.4%），但會出現膝蓋彎到 145°、手臂擺到身後藏起來這類不自然的姿勢。加上先驗和平滑項後，膝蓋最多約 17°，左右髖也會交替擺動。
- **已知限制**：
  - 正面重疊率比修正頭部前少約 1 個百分點（見 6.2）。
  - 正面和側面同一格編號是否真的是同一時刻，只是假設。
  - 只有輪廓時，被身體遮住的四肢原本就無法唯一判定。

### 6.2 修正 LPC 頭部的點頭偏差

- **病因**：舊模型的頭和軀幹在側面都比 LPC 偏前約 2～3 px，LPC 的背也比較厚。反推為了蓋住背後，就讓軀幹後仰約 6°，頭再用點頭往前補回來。所以這是頭和軀幹前後位置的偏差，不只是頭形不對。
- **修法**：把骨架擺成直立（骨盆、脊椎、頸部的角度歸零），四肢沿用反推結果，再用座標下降法調整頭、下巴、軀幹的位置，讓 9 格雙視角第 30～106 列的不吻合像素最少（6546 → 4640）。結果是頭往下移 2 px、往後移 3 px，軀幹往後移 3 px，頭形大小不變。
- **結果**（混合式，9 格，同一台機器前後對照）：

| | 平均點頭角度絕對值 | 脊椎前彎 | 正面 IoU | 側面 IoU |
|---|---|---|---|---|
| 修正前 | 22.4°（每格 +15～+32°） | −4～−9° | 89.8% | 85.6% |
| 修正後 | 5.0°（−9～+9°） | −6～+4° | 88.7% | 85.8% |

- 只改前後位置、頭不往下移時，平均點頭 9.7°，重疊率 88.9%／86.4%。最後選了點頭角度較小的版本。
- 歪頭角度（正面）在第 4、8 格仍有約 ±14°，還沒處理。

### 6.3 步態移植到寫實體型

- 兩種體型共用同一組 22 個自由度，所以「套用到寫實體型」按鈕把反推出的 9 格角度原封不動套上，以每格 110 ms 循環播放。
- 沒有做比例換算：LPC 腿短頭大，同樣的角度在寫實體型上步幅會比較大。
- 反推出的髖外展有時達 −19°（內收），寫實體型的正面會看到雙腿往中線交叉。這是 LPC 腿在正面幾乎重疊造成的，還沒處理。

### 6.4 多角色與揮砍、施法

- **素材**：`examples/assets/lpc-atlas.png` 收了 5 組角色（男、女、壯碩男、少女、女・小頭），每組 3 個動作（走路 9 格、揮砍 6 格、施法 7 格），各有正面與側面。來源與授權見 `LPC-CREDITS.md`。
- **體型校正**：其他角色的體型都從男性參數出發，自動調整頭、下巴、軀幹的位置與半徑、肩寬、髖寬、四肢粗細。做法和 6.2 相同：用坐標下降法，讓幾格影格的輪廓不吻合像素最少，輪廓不吻合減少約 25～47%。壯碩男只用走路校正時，手臂抬起來後點頭偏差約 20°；把揮砍、施法的影格也一起拿來校正後才改善。
- **揮砍、施法的反推設定**：
  - 肩、肘的先驗放寬：肩前舉的 σ 從 35° 放寬到 90°，外展從 25° 到 70°，肘從 30° 到 60°。
  - 前後格的平滑項 σ 從 20° 放寬到 45°。原本是 20°，動作變化快的揮砍因此被拉回上一格，手臂抬不起來：少女的肩最大只有 6°。
  - 另外強制從「單手往前抬 90°」的姿勢起跑。
- **結果**（混合式；IoU 依序為正面／側面；「頭部絕對俯仰」= 骨盆前傾＋脊椎前彎＋點頭）：

### 6.5 動漫體型（6 頭身）與衣物物理（L6）

- **為什麼要做**：LPC 體型是為了對齊 Q 版輪廓而擬合的，頭約佔身高 1/3，腿是手的 2～3 倍粗。深蹲這類 LPC 沒有的動作，看起來會擠成一團。動漫體型只負責呈現，不拿來反推。
- **比例**：頭高約身高的 1/6，髖關節以下約佔一半；四肢各用一顆膠囊（大腿半徑 4.4、上臂 2.8）；腰細、肩窄，胸廓比例中性。臉用大眼睛色塊（瞳孔、高光）和較低的瀏海表現。
- **衣物物理**：用 Verlet 質點，每步更新 x ← x + (x − x_prev)(1 − 阻尼) + g·dt²，再反覆套用以下兩種修正：
  - 距離約束：兩個質點之間保持原本的距離。
  - 碰撞：p += n·ReLU(r − |p − c|)，碰到碰撞體就沿法線推出去。
  - 兩者都只用到乘、加、ReLU。
  - 雙馬尾：每邊 6 個質點（根部固定在頭上），會碰撞頭、胸、肩。
  - 短裙：12 條從腰部垂下的鏈，每條 4 個質點（根部固定在骨盆上）；同一層相鄰的鏈互相牽住，維持裙擺的圓周。碰撞體是骨盆（球）和兩條大腿（膠囊）。
  - 物理關閉時，或剛換姿勢時，用大阻尼直接算 80 步，讓衣物停在靜止狀態。
- **實測**：
  - 停止走路 4 秒後，質點最大速度 0.0006 px／幀，表示會靜下來。
  - 裙子穿入大腿碰撞體的最大深度：深蹲 0.54 px、踢腿 0、走路 0。碰撞體半徑 6.4，比大腿本身多 2 px 的餘裕，所以看不到穿模。
- **已知限制**：
  - 裙子由細膠囊拼成，邊緣有鋸齒。
  - 頭髮沒有和手臂碰撞，手舉過頭時可能穿過頭髮。
  - 物理步長跟隨畫面更新率，畫面卡頓時晃動幅度會變小。

### 6.6 時間軸：關鍵影格＋貝茲補間（Spine 式逐格）

- **補間**：第 k 格的每個關節角度 θ = θa + (θb − θa)·e(t)，t = (k − fa)/(fb − fa)。e 是這一段的 cubic-bezier(x1, y1, x2, y2)，和 CSS、Spine 曲線編輯器是同一種定義：先由時間 x 用二分法解出參數 s，再取 y(s)。y 可以超出 0～1，做出回彈。關鍵格可以有很多個，每一段各有自己的曲線。
- **腳底鎖定**（簡易 IK）：讓指定腳的腳踝，水平位置維持在這一段開頭的位置。做法是用逐關節試探調整髖（屈伸、外展）和膝，並加一點正則項，避免偏離補間結果太多；再由踝角補償，讓腳掌的俯仰角維持不變。垂直方向交給地面約束。
- **匯出**：N 格 × 2 列（上排正面、下排側面），每格 81×144，背景透明。動漫體型的衣物物理照「每秒格數」逐格推進，所以匯出的 sprite sheet 也有次級運動。
- **實測**（無頭瀏覽器）：
  - 首格、末格和擷取的姿勢完全一致，中間格都在關節限位內。
  - 緩入緩出曲線在 t = 0.25 的值是 0.129，和 CSS 的 ease-in-out 一致。
  - 腳踝水平漂移（走路 → 踢腿，12 格）：不鎖時 37.6 px；鎖左腳 0.18 px，鎖右腳 0.09 px。
  - 匯出的圖是 972×288、RGBA，背景透明。
- **已知限制**：
  - 角度是逐個自由度線性內插（尤拉角），大角度同時繞兩軸轉時，路徑可能不是最短的。
  - 腳底鎖定只鎖一隻腳，也不會自動判斷哪隻腳是支撐腳。

### 6.7 圖片 → sprite（handwired）

- **B：關節 → 姿勢 → 取色**：
  - 使用者在圖上依序點 14 個關節（臉中心、脖子、雙肩、肘、腕、髖、膝、踝）。
  - 模型關節做正面投影後，和照片點做「縮放＋平移」對齊，縮放 s 只在立正姿勢時用最小平方閉式解算一次，之後固定；接著用逐關節試探降低殘差，並加上自然姿勢先驗：骨盆 σ 8°、脊椎 15°、頸 12°、肩 90°、肘 60°、髖和膝 45°。
  - **踩過的雷**：一開始每次都重新估 s。結果身體往鏡頭倒時，模型在正面圖上變小、s 變大，誤差看起來反而變小。求解器因此選了「整個人往前倒」的姿勢，正面看起來對，側面明顯錯。把 s 固定後才正常。
  - 取色：在臉、頭頂、上衣、裙褲、小腿、鞋的位置各取一塊方塊，算各通道中位數，再乘上固定倍率得到亮、中、暗三階。
- **A：像素化管線**（每層權重固定）：
  1. 平均池化縮小。
  2. 去背：取邊框的中位色當背景，前景 = ReLU(和背景的距離 − 38) > 0。
  3. 調色盤：用中位切分法挑色；每個像素經過線性層，分數 = 2x·c − |c|²，取分數最高的顏色。
  4. 去雜點：3×3 多數決。
  5. 描邊：亮度做 Sobel，|g| = ReLU(g) + ReLU(−g)，超過門檻、而且比鄰近平均暗（拉普拉斯為正）才畫，避免線條變成兩條；遮罩外圍用 3×3 取最大（膨脹）補上外框。
  - 每一步都輸出縮圖，可以逐層檢查。
- **實測**（合成測試圖）：
  - 測試圖的做法：用動漫體型、已知姿勢和指定配色畫出正面圖，放大 6 倍並平滑，換成淺色背景；關節位置由真值投影而來。
  - 關節投影誤差：平均 0.31 px、最大 1.03 px（以 sprite 像素計）。
  - 角度平均誤差 10.5°。主要來自只有一個視角時無法分辨前後的關節，例如右肩前舉的真值是 0°，反推出 −45°。
  - 六個部位的取色中，膚色、頭髮、上衣、裙子、小腿與指定色完全一致；鞋子取到亮暗混合，略偏暗。
- **未驗證**：沒有用真實的動漫圖測過。這類圖常有漸層、花紋、頭髮擋住肩膀，取色和去背門檻可能需要調整。

### 6.8 借用 agent-sprite-forge 的後製與品質檢查

參考 [0x0funky/agent-sprite-forge](https://github.com/0x0funky/agent-sprite-forge)（MIT）的文件，概念自行以 JavaScript 重新實作，沒有複製程式碼。

| # | 項目 | 做法 | 用在哪裡 |
|---|---|---|---|
| 1 | OKLab | sRGB → 線性 → 矩陣 → 立方根 → 矩陣，權重全部固定；量化層改在 OKLab 空間算分數 2x·c − \|c\|² | 照片像素化、取色、顏色鎖定 |
| 2 | 確定性 k-means++ | 固定種子的 mulberry32 亂數初始化，在 OKLab 中迭代 12 次；中位切分保留為選項 | 照片像素化 |
| 3 | 二值 alpha＋去孤立像素 | 8 個鄰居都不同色就改成多數色；前景單點刪掉；描邊後再清一次 | 照片像素化、sprite sheet 匯出 |
| 4 | 選擇性描邊（selout） | 描邊色 = 相鄰區塊顏色在 OKLab 中把 L 乘 0.52、色度乘 1.15 | 照片像素化（預設開）、即時渲染（開關，預設關） |
| 5 | 品質檢查數字 | 色數、alpha 階數、孤立像素、量化平均色差、和縮小圖差距 dE > 0.08 的比例（超過 5% 標 ⚠️） | 照片像素化、匯出（每格） |
| 6 | 顏色鎖定 | 所有格子一起建一個 OKLab k-means 調色盤（預設 24 色），每格量化到同一套顏色 | sprite sheet 匯出 |
| 7 | 跑速 | 每格找著地腳（腳踝較低者），量它往後移的量；平均值 = 建議前進 px／格；預覽可開「跟著前進」 | 時間軸 |

**實測**（無頭瀏覽器）：
- 照片像素化（合成測試圖，12 色）：
  - 量化平均色差：中位切分（RGB）0.061 → k-means++（OKLab）**0.057**。
  - 孤立像素：清理前約 84 個 → **0～2 個**。
  - alpha 階數 = 2。
  - 和縮小圖差距大的像素約 18%：測試圖是模糊放大的，邊緣混色多，12 色不夠，所以標 ⚠️。
- sprite sheet 匯出（動漫體型，立正 → 踢腿，12 格）：
  - 每格色數最多 31 → **23**，整張 34 → **24** 色。
  - 孤立像素總數 564 → **0**。
  - alpha 階數 = 2。
- 跑速：以預先反推的男性走路 8 格當關鍵格（寫實體型），建議前進 6.51 px／格。著地腳的水平滑動：不前進時每格 6.87 px，跟著前進時 **0.36 px**。

**限制**：
- 照片的去背門檻是 OKLab 距離 0.035，背景和人物顏色接近時會挖錯。
- 模糊或半透明的邊緣會變成灰色外框。
- 跑速只看著地腳的前後方向；揮砍這類原地動作算出來接近 0，屬於正常。
- 「跟著前進」超出畫面時會瞬移回來，動漫體型的衣物物理會在那一格重設。

### 6.9 去背：四種 handwired 工具

上傳圖片後，先做出一張遮罩，標出哪些像素是人物、哪些是背景。像素化（A）和取色（B）都只用遮罩裡的人物像素；像素化的平均池化改用預乘 alpha，被挖掉的背景不會混進邊緣顏色。

| 工具 | 做法 |
|---|---|
| ① 自動 | 取邊框的 OKLab 中位色當背景；前景 = ReLU(色差 − 容許度) > 0 |
| ② 魔術棒 | 從點的位置往四個方向擴散，每一步的閘門是 ReLU(容許度 − 和起點的色差) > 0 |
| ③ 骨架引導 | 人物種子是 14 個關節連成的骨頭線；背景種子是邊框，以及離所有骨頭都很遠的像素（軀幹長 × 0.35；頭部附近放寬到「臉中心到脖子」× 2.2 的圓）。每個像素歸給「路徑上最大色差最小」的那一邊（minimax 路徑，等同分水嶺），用 256 個桶的佇列計算 |
| ④ 筆刷 | 保留或刪除，可調大小；可以復原 |
| 描線歸人物 | ①、③ 之後執行：把「緊貼人物、OKLab 亮度 L < 0.45、比旁邊的人物暗 0.05 以上（或和剛併進來的描線一樣暗）」的像素逐步併回，最多 8 輪 |

**實測**（合成圖：動漫體型放大 5 倍，背景是漸層加 40 個隨機色塊，其中一塊和頭髮同色；以真實遮罩算重疊率 IoU）：

| 方法 | IoU |
|---|---|
| 不去背 | 17.8% |
| ① 自動 | 22.6%（背景太雜，邊框色不能代表背景） |
| ② 魔術棒點四角加上緣（5 下） | 26.6% |
| ③ 骨架引導 | **93.6%**（耗時約 0.25 秒） |
| ③ ＋ 魔術棒點 3 下 | **98.9%** |

- 剩下的錯誤是被手臂和雙馬尾圍住的背景，用魔術棒可以補掉。
- **過程中修的問題**：
  - 一開始深色描線全被分到背景（漏掉約 4,000 px），加上「描線歸人物」才修好。
  - 描線有好幾 px 寬時，第一版只會併第一圈，後來放寬為「可以沿同樣暗的描線往外併」。
  - 我的測試腳本產生真實遮罩時開了平滑，讓遮罩多出 1～2 px，一度把分數算低了。
- **限制**：
  - 人物和背景顏色接近時，骨架引導仍會搶錯，要用筆刷修。
  - 頭髮如果超出頭部的放寬範圍（例如很長的雙馬尾），會被當成背景種子剪掉，要用保留筆刷補回。
  - 只用合成圖測過，沒測過真實的動漫圖。

### 6.10 照片體型：從一張圖量出角色

套用現成體型（動漫、寫實）時，比例、髮型和衣服都對不上，輪廓相似度上不去。所以改成直接從照片量出體型：

1. **座標換算**：人物最高點到最低點縮成 128 px、腳底貼地、髖部中點放在畫面中線。照片遮罩和顏色縮到 81×144（預乘 alpha，覆蓋率 ≥ 0.5 才算人物）。
2. **骨架**：直接用使用者點的 14 個關節當靜止姿勢，所以「站姿」就是照片的姿勢，所有動作都從這個姿勢開始彎。
3. **量寬度**：
   - 肢體：沿骨頭的垂直方向量「包含這一點的整段寬度」，並把膠囊平移到量到的中心。整段太寬（代表貼到軀幹）時，改成往身體外側量。
   - 軀幹：從脖子到髖切 6 片橢球。
   - 頭髮：從頭頂到脖子分 3 層，每層依輪廓寬度各畫一顆橢球。
   - 手：沿前臂延伸到輪廓盡頭。腳：從腳踝往下到地面。
4. **取色**：每個形狀沿自己的骨頭取 OKLab 中位色，乘上固定倍率做成亮、中、暗三階；臉沿用動漫臉的五官規則。
5. **微調**：每個形狀兩個參數（寬度、左右位置），用坐標下降（步長 1 → 0.5 px）直接讓正面輪廓 IoU 最大。

**實測**（使用者提供的動漫圖：純灰背景、黑色上衣與長褲、約 8 頭身）：

| 版本 | 正面輪廓 IoU |
|---|---|
| 套用動漫體型 | （髮型、衣服都不同，未量） |
| 照片體型，第一版（肢體取較短一側） | 72.9% |
| 改量整段寬度 | 75.2% |
| 加上中心平移、頭髮 3 層 | 81.7% |
| 再加坐標下降微調 | 88.5% |
| 照片貼圖＋頭髮 8 層 | **88.3%**（色差 0.139 → **0.069**） |

- 重疊處的平均色差是 0.139（OKLab），屬於偏高：軀幹切片各自取色，所以乳溝、露腰處會變成一條一條的膚色橫帶；臉部的五官只用規則畫，不是照片的長相。
- **限制**：
  - 只量了正面；側面的厚度用正面寬度乘固定比例估算。
  - 靜止姿勢就是照片的姿勢，從這裡加角度時，衣服不會跟著變形（例如褲管不會皺）。
  - 測試圖沒有放進 repo。

**照片貼圖**（6.10 的延伸）：
- 渲染時每個像素都知道自己在「靜止姿勢下的位置」，原本拿來畫位移熱圖。照片體型的靜止姿勢就是照片的姿勢，所以正面可以直接回照片的同一個位置取色；落在輪廓外時，找 3×3 內最近的人物像素。
- 擺出其他姿勢時，顏色會跟著骨頭移動，原理和蒙皮貼圖相同。
- 側面看到的後半邊（橢球局部 z < 0）照片上看不到，改用該形狀沿骨頭取的材質色。
- 效果：胸口的 V 領、露腰、臉都和照片一致，軀幹不再出現膚色橫帶；重疊處的色差從 0.139 降到 0.069。
- 限制：
  - 側面的前半邊借用正面的顏色，所以側面的鞋子會變成膚色（正面看到的是腳背）。
  - 手臂往前舉時，貼圖會被拉長。

### 6.11 軟組織（L6）：胸、肚子、臀、大腿、臉頰

- **模型**：每個部位是一組附在骨頭上的彈簧阻尼（三個方向）：d'' = −ω²d − 2ζωd' − g·a。其中 ω = 2πf；a 是錨點的加速度，用前後三幀的二階差分算，姿勢瞬間跳動時限制在 6000 px/s² 以內。位移 d 用 clampR（ReLU）限在上限內。數值積分用半隱式歐拉，每幀 8 個子步。
- **體積守恆**：往下晃時變高變窄，往上時變矮變寬（高 × k、寬和厚 × 1/√k），k 限在 0.8～1.25。
- **預設值（自然）**：

| 部位 | 頻率 | 阻尼 ζ | 上限 |
|---|---|---|---|
| 胸部 | 4 Hz | 0.25 | 1.5 px |
| 肚子 | 3 Hz | 0.3 | 1.0 px |
| 臀部 | 3.5 Hz | 0.3 | 1.0 px |
| 大腿 | 5 Hz | 0.35 | 0.8 px |
| 臉頰 | 7 Hz | 0.4 | 0.4 px |

  頻率依「人體軟組織每秒約 3～7 次」的印象設定，未經即時檢索（⚠️）。可以用「程度」滑桿整體放大（1× = 自然）。
- **套用範圍**：
  - 照片體型：軀幹切片（胸、肚子、臀）、大腿、新增的兩顆臉頰橢球（貼圖會取到照片的臉頰）。
  - 動漫體型：胸廓、細腰、骨盆、大腿、臉頰。
  - 寫實體型：骨盆、大腿、臉頰。軀幹是一整顆橢球，整顆晃動會和手臂脫開，所以不套用。
  - 大腿只讓靠髖的一端跟著晃（權重 0.35），靠膝的一端只動 0.1，避免和小腿脫開。
- **實測**（無頭瀏覽器；給一次初速度，以 240 Hz 推進 2 秒）：

| 部位 | 設定的阻尼後頻率 | 實測 | 誤差 | 1 秒後的位移 |
|---|---|---|---|---|
| 胸部 | 3.87 Hz | 3.87 Hz | −0.1% | 0.0004 px |
| 肚子 | 2.86 Hz | 2.86 Hz | −0.2% | 0.0011 px |
| 臀部 | 3.34 Hz | 3.33 Hz | −0.2% | 0.0004 px |
| 大腿 | 4.68 Hz | 4.71 Hz | +0.5% | 0 |
| 臉頰 | 6.42 Hz | 6.49 Hz | +1.1% | 0 |

- 走路 3 秒（CPG），最大位移 1.5 px，剛好碰到胸部的上限。破洞數：動漫體型開關前後都是 2；照片體型 3 → 2，沒有增加。照片體型的輪廓相似度維持 88.3%。
- **順手修正**：匯出時的顏色鎖定原本依面積加權，幾乎全黑的角色會把膚色擠掉，臉變暗。改成「每種顏色只算一次」後，膚色保留下來。
- **限制**：在 81×144 的畫面上，自然程度的晃動只有 1～1.5 px，看起來很細微；照片只有正面，前後方向的晃動只看得到側面。

### 6.12 脊椎分節：前後左右彎腰

- **骨架**：骨盆和胸之間原本是一根硬骨頭，改成 4 節：sp1 腰椎下段、sp2 腰椎上段、sp3 胸椎下段、chest 胸椎上段，肩和頭接在 chest 上。支點放在「骨盆上方 2 px」到「兩肩中點」之間，依序在 0、0.3、0.55、0.8 的高度。
- **控制方式不變**：「脊椎・前彎／側彎」兩個滑桿的角度依比例分給 4 節：前彎 30%、30%、20%、20%（以腰椎為主）；側彎 20%、25%、30%、25%。比例依印象設定，未經即時檢索（⚠️）。依使用者要求，這一版先不做扭轉。
- **梯度**：每個自由度改成可以影響多個關節；雅可比是 4 節「旋轉軸 × 力臂 × 權重」的總和。
- **軀幹跟著彎**：綁在 chest 上、比較高的橢球切成約 6 px 高的薄片，寬度依原橢球的輪廓縮（薄片高 1.15 倍、寬多 6%，相鄰薄片多重疊，邊緣才不會有鋸齒）；每個形狀再綁到「支點在它下方、最靠近的那一節」。
- **展示**：
  - 「顯示脊椎」：沿著 4 節支點到頸部的折線，畫出 17 節椎骨（腰椎 5 節較大、偏黃，胸椎 12 節）。
  - 新增預設姿勢：前彎、後仰、左彎、右彎。
  - 「▶ 脊椎繞圈」：前彎和側彎相差 1/4 週期，依序前、側、後、側循環。
- **回歸驗證**：
  - 只改骨架（還沒切片）時，脊椎角度為 0 的畫面和修改前逐像素相同（4 種體型 × 4 個姿勢 × 正側面，差異 0 位元組）。
  - 切片後，站姿畫面和原本差 0.04%（照片）～2.4%（LPC）的像素。
  - 隨機目標反推（雙視角，固定種子 3 題）：平均誤差 1.24 → 1.11 px，沒有變差。
  - LPC 15 組內建結果重跑後，平均輪廓重疊率比修改前差 −0.14 個百分點，最大降幅 0.94，都在 1 個百分點以內。
  - 照片體型的相似度維持 88.3%。
- **修正（腳底滑動）**：腿是骨盆的子骨頭，骨盆一轉，整雙腿跟著繞髖部擺動；地面約束只管垂直，不管前後，所以側面看起來腳在滑。改成「脊椎繞圈」只動脊椎；前彎、後仰的骨盆前傾由髖關節反向補償同樣角度；左右彎不再側傾骨盆。腳踝的水平位移：繞圈 8.8 → 0 px，前彎 19.4 → 0.6 px，後仰 8.7 → 0.4 px，左右彎 5.5 → 0 px。
- **限制**：
  - 沒有扭轉，所以轉身的動作做不出來。
  - 預設姿勢以外，骨盆前傾的補償靠「站立模式」：拖骨盆滑桿時，髖關節自動反向補償同樣的角度（前傾 Δ → 兩髖前抬 +Δ；側傾 Δ → 右髖外展 −Δ、左髖外展 +Δ）。實測腳踝水平位移：前傾 −20°～30° 時從 31 px 降到 1～1.5 px，側傾 ±15° 時從 16.5 px 降到 0.7～0.9 px。剩下的位移來自髖關節不在骨盆轉軸上；超出髖的活動範圍時只能補到極限。補償只在拖滑桿時作用，不影響反推、預設姿勢和動畫。
  - 骨盆本身仍是一塊，坐下時腰臀的變形不細緻。
  - 椎骨只是畫在骨架上的示意圖，不參與碰撞或渲染。

### 6.13 多視角擬合：正面＋側面

- **輸入**：正面圖點 14 個關節；側面圖（人物臉朝右）點 8 個關節：臉中心、頸、肩、肘、腕、髖、膝、踝。兩張都縮到身高 128 px，以腳底對齊；正面的髖放在 x = 40.5，側面的髖放在 z = 0。
- **厚度不用再猜**：
  - 關節的前後位置（z）直接取自側面圖；脊椎各節依高度在髖和頸之間內插。
  - 每顆橢球（軀幹、裙子、頭髮）在自己的高度，取側面輪廓中、離預估位置最近的那一段，當作前後範圍。
  - 手腳的膠囊沿側面的骨頭線決定 z；鞋子從後跟延伸到腳尖；臉放在頭的最前面。
- **側面貼圖**：側面畫面的座標（40 + z, y）直接回側面照片取色。
- **裙子延伸**：髖以下、兩腿之間仍是人物時，繼續往下切片，直到露出腿縫。百褶裙、洋裝都適用；長褲很快就會停。
- **微調**：有側面圖時，目標改成正面和側面 IoU 的平均，參數也多了前後位置和厚度。
